# 需求 · 审查流（问题闭环）

## 背景

Review 时勾选 commit 批量"标记通过 / 标记有问题（意见）/ 重置待审"。用户反馈两个缺口：
1. "标记有问题"后**没有地方看到问题内容**（意见存了但没展示）
2. 已存在问题的 commit **仍可随意"标记通过"**（缺少审批前置约束）

## 场景与实现

| 诉求 | 实现 |
|---|---|
| 问题要可见 | commit 信息区（右侧下方）**置顶显示**「⚠ 待解决问题（N）」+ 每条 commit 的**意见原文**；单个 commit 详情同样显示「⚠ 问题：…」 |
| 有问题必须先解决 | 点「标记通过」时扫描勾选中 `reviewStatus == 'issue'` 的 commit → **弹窗拦截**并列出问题清单（提示先解决并「重置待审」后再通过） |

## 边界

- "解决"的操作路径：修复代码后手动「重置待审」（或重新标记）——本轮不做更重的状态机（如"问题闭环"独立状态）
- 拦截在**插件 UI 层**（后端仍允许 API 直接改状态；如需强约束可后续加到后端）

## 验收

- 标记有问题（填意见）→ 信息区顶部出现「⚠ 待解决问题」含意见原文
- 勾选该 commit → 点「标记通过」→ 弹「无法标记通过」清单
- 重置待审后再点通过 → 正常
