# 需求 · Diff 行级评论

## 背景

Review 时看到有问题的代码行，需要**就地留评**（类似 GitLab/GitHub 的 PR 行级评论），事后可回溯；
评论归属于**任务节点 + 具体文件 + 行号**，不丢上下文。

## 场景

1. **添加**：进入节点 Review → 打开 diff → 选中若干行 → 顶栏「评论」→ 输入内容 → 保存
   - 自动记录：**文件路径 + 起始/结束行号 + 选中片段（≤500 字）+ commit（单选提交时）+ 节点**
2. **查看**：顶栏「评论列表」→ 弹窗按文件+行号列出全部评论（●待处理 / ✓已处理 + 计数）
3. **程序化**：Qoder/CLI 经 MCP 读写评论（`comment_add/list/update/remove`）；网页/脚本经 HTTP

## 边界

- 评论跟随"文件路径+行号"，代码行变动后不自动重定位（行号可能漂移）
- 本轮不做"行尾 Inlay 气泡"（v2 候选）；现状为弹窗列表 + 顶栏入口
- 非 task-board diff 编辑器（如普通文件）不产生评论上下文（提示）

## 验收

- diff 选中 3 行 → 「评论」→ 保存 → 「评论列表」可见（带文件 L 起始-结束 + 内容）
- `curl /api/comments?filePath=…` 可查；`comment_add` MCP 可写
- 空内容被拒绝（测试覆盖）
